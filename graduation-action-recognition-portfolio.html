Project Functions

项目功能

本系统不是单独训练一个动作分类模型，而是围绕摄像头输入、动作识别、结果展示、日志记录和样本回流构建的一套完整实时识别系统。

1

实时动作识别

系统接入普通 RGB 摄像头或视频片段，连续构建输入窗口，识别 walking、running、standing、waving、clapping、sitting 六类动作。

2

多模态输入构建

每段动作输入不只看单帧画面，而是同步构建 RGB 图像、光流信息和人体姿态关键点序列，用三类特征描述动作。

3

结果显示与日志记录

界面实时显示动作类别、置信度、推理延迟、缓存状态和姿态状态，并把动作变化、延迟和异常信息写入日志，便于复盘。

4

样本采集与回流

当某类动作识别不稳定时，可以通过样本采集模块录制真实场景视频，按类别保存后补充到后续训练流程中。

Implementation Route

实现方法与技术路线

这一部分按系统真实运行顺序说明：先用 OpenCV 获取视频流，再构建 RGB、光流和姿态三类输入，随后通过 PyTorch 训练的三分支融合模型完成分类，最后接入 OpenVINO 后端输出实时结果。

系统主链路为：视频输入 -> 预处理 -> 三模态特征 -> 模型推理 -> 结果显示与日志 -> 样本回流。右侧样本采集与模型更新用于补充真实场景数据。

1. 视频采集与预处理

实时入口由 realtime_multimodal_action_rec.py 调度，摄像头管理使用 OpenCV 和 camera_utils.py 完成打开、预热、读取重试。输入帧会统一进行 resize、BGR 转 RGB、归一化和缓存。

2. 三模态特征构建

系统同步构建三类输入：RGB 帧保留外观信息，光流帧描述相邻帧运动变化，MediaPipe Pose 提取人体关键点序列。三类特征按同一时间窗口对齐后送入模型。

3. 三分支融合模型

核心模型为 MultiModalActionNet。RGB 分支和 Flow 分支使用 MobileNetFeatureExtractor 提取视觉特征，Pose 分支使用 PoseTemporalEncoder 编码姿态时序，融合后输出六类动作概率。

4. 推理部署与结果反馈

multimodal_inference_backend.py 将 PyTorch 与 OpenVINO 封装为统一的 predict_proba() 接口。训练后模型接入 OpenVINO，在不改变界面逻辑的情况下完成 CPU 推理加速，并把类别、置信度和延迟写入界面与日志。

视频输入 OpenCV VideoCapture 取流，支持摄像头预热和读取重试
图像预处理 尺寸调整、BGR 转 RGB、像素归一化和输入维度整理

结果反馈 OpenVINO 后端返回类别、置信度、延迟，并同步界面和日志

Data & Model

数据处理与模型训练

模型训练流程包括样本整理、预处理、三模态特征构建和 PyTorch 训练验证四个环节，用于支撑最终部署模型的生成与筛选。

1

样本整理

围绕 walking、running、standing、waving、clapping、sitting 六类动作整理视频片段，并按类别保存。

2

预处理

对视频帧进行尺寸调整、颜色空间转换和归一化，使不同来源的视频可以进入统一输入格式。

3

特征构建

RGB 负责外观信息，光流负责动作变化，姿态关键点负责人体结构，三类输入共同参与识别。

4

训练验证

用 PyTorch 训练多分支模型，验证时统计各动作类别准确率，并以验证集表现作为模型选择依据。

Deployment & Test

部署测试：为什么最终选择 OpenVINO FP

测试环节围绕准确率、推理延迟和功能完整性展开，用于比较不同后端方案并确定最终部署版本。

准确率测试

OpenVINO clip12 验证集共 7702 个样本，总体准确率为 86.26%；sitting、standing、clapping 表现更稳定，running 与 walking 是主要混淆对。

实时性测试

OpenVINO FP 平均推理延迟为 23.64 ms，P95 延迟为 25.42 ms，相比 PyTorch 推理延迟更低，更适合普通 CPU 条件下连续运行。

后端选择

PyTorch 用于训练和调试，OpenVINO FP 用于最终部署；INT8 虽然平均延迟降到 14.34 ms，但准确率下降到 0.8056，因此没有作为主版本。

功能测试

摄像头取流、图像预处理、三模态缓存、模型推理、结果显示、日志记录和样本采集均按功能项验证通过。

Research Results

研究结果：完成一套从数据、模型到部署验证的实时识别系统

系统已经实现六类动作识别、三模态特征融合、OpenVINO 推理部署、实时结果显示、日志记录和样本回流训练。实验结果表明，当前方案在普通设备条件下具备可运行性和较好的实时性。

Conclusion

论文结论：系统可运行、实时性满足需求，但步态区分仍需加强

结论部分概括系统完成情况、性能表现、主要不足及后续优化方向，用于总结本项目的工程实现效果和应用边界。

结论 1：系统链路完整

系统完成视频输入、预处理、三模态特征构建、模型推理、结果显示、日志记录和样本采集，具备完整应用流程。

结论 2：实时性较好

OpenVINO FP 平均推理延迟约 23.64 ms，能够支撑普通 CPU 条件下的实时识别运行。

结论 3：总体效果可用

OpenVINO clip12 验证集总体准确率为 86.26%，standing、clapping 和 sitting 等类别识别较稳定。

不足 1：步态类动作易混淆

running 与 walking 主要依赖下肢节奏和位移变化，近景画面下下肢信息不完整时仍容易混淆。

不足 2：真实样本还需扩充

不同光照、拍摄距离、入镜比例和人物差异仍需继续补充，以提升复杂场景下的泛化能力。

后续方向

继续补充真实场景数据，优化时序建模和融合策略，并扩展更多动作类别。

Evaluation

实验结果：OpenVINO FP 在准确率与延迟之间更均衡

从验证集准确率看，standing、sitting 和 clapping 表现稳定；从实时性看，OpenVINO 相比原始 PyTorch 推理明显降低延迟。INT8 更快，但准确率下降，因此 OpenVINO FP 更适合作为当前系统的部署版本。
