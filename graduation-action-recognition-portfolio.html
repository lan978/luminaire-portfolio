Real-Time Human Action Recognition

实时人体动作识别系统的设计与实现

面向普通笔记本与普通 RGB 摄像头场景，构建一套从视频采集、三模态特征构建、动作识别、结果显示到样本回流训练的完整实时视觉系统。

作者姓名：蓝哲琦 指导老师：王元斌 学院专业班级：人工智能学院 · 软件工程 2022 级 3 班

Main Work

主要工作

本课题不是只完成一次模型训练，而是围绕“普通摄像头实时动作识别”完成从需求分析、数据准备、模型构建到部署测试的完整过程。

1

明确目标与技术路线

先完成文献调研和需求分析，明确系统要支持普通摄像头实时输入，识别六类常见动作，并具备结果显示、延迟统计和日志记录能力。

2

搭建视频数据管道

使用 OpenCV 完成摄像头取流、帧裁剪、resize 和归一化处理；围绕 walking、running、standing、waving、clapping、sitting 整理与采集视频样本，并按类别保存。

3

构建多模态识别模型

对比动作识别路线后，采用 RGB、光流和姿态关键点三类输入；基于 PyTorch 构建多分支模型，使系统同时学习外观、运动和人体结构特征。

4

完成训练、部署与测试

设计训练流程并保存模型结果，再接入 OpenVINO 推理后端降低延迟；最后通过准确率、实时性和功能测试分析系统效果，并针对错误类别提出优化方向。

从 0 到 1 的核心链路是：调研与需求分析 -> 视频样本采集和预处理 -> RGB/光流/姿态三模态建模 -> PyTorch 训练 -> OpenVINO 部署 -> 摄像头实时演示与测试分析。

Topic Reason

选题原因

选择这个题目，一方面来自个人对计算机视觉和智能交互的兴趣，另一方面也来自实际研究和系统实现中暴露出的现实问题。

个人兴趣

在课程学习和项目实践中，我对计算机视觉、深度学习和人机交互方向比较感兴趣。人体动作识别能够把摄像头输入、模型训练和实时界面结合起来，适合作为毕业设计进行完整实现。

相比只做静态图像分类，这个课题更贴近真实系统开发，需要同时考虑算法效果和工程运行。

理论研究中的问题

现有动作识别研究已经证明 RGB、光流和骨架特征都具有价值，但很多方法更偏向公开数据集或离线实验。

在普通摄像头近景场景中，人体可能局部入镜、姿态会抖动、背景和光照会变化，这些问题会让模型在实际运行时不够稳定。

实际场景中的痛点

真实应用不只关心模型是否能分类，还关心摄像头能否稳定取流、推理能否及时返回、结果能否直观显示。

例如 walking 和 running 在近景画面中容易因为下肢信息不足而混淆，这类问题越来越明显，也说明普通设备场景仍有进一步研究价值。

选题意义

理论意义

从理论意义来看，本文对普通摄像头近景场景下的多模态动作识别进行了补充和细化。

通过 RGB、光流和姿态关键点三类特征融合，说明动作识别不仅要看人体外观，也要看运动变化和人体结构变化。

从实际意义来看，本文解决了普通设备条件下动作识别系统如何完整运行的问题。

系统能够完成摄像头取流、动作分类、置信度显示、延迟统计、日志记录和样本采集，为类似低成本视觉应用提供参考。

核心结论

本文得出的核心结论是：多模态特征融合结合 OpenVINO 部署优化，可以在普通摄像头和普通 CPU 条件下实现可用的实时人体动作识别。

Innovation Highlights

论文创新点

本部分围绕系统相较于单一离线分类实验的创新展开，重点说明完整系统闭环、多模态特征融合、普通设备部署和样本回流优化。

本文围绕“视频输入 -> 三模态特征 -> 模型推理 -> 结果显示 -> 样本回流”形成完整系统链路，这是本文创新点的总体结构说明。

创新点 1：完整系统闭环

系统不是只做离线分类，而是把摄像头取流、预处理、特征构建、模型推理、结果显示、日志记录和样本回流连成完整流程。

创新点 2：多模态融合

系统不是只依赖单帧图像，而是将 RGB、光流和姿态关键点三类特征结合起来，从外观、动态和人体结构三个角度判断动作。

创新点 3：普通设备部署

模型训练完成后接入 OpenVINO 推理后端，在普通 CPU 环境下平衡准确率和推理速度，使系统不只停留在离线测试。

创新点 4：样本回流优化

系统加入样本采集、日志记录和后续训练更新入口，使识别效果可以根据真实场景中的错误案例继续优化。

Conclusion

论文结论：系统可运行、实时性满足需求，但步态区分仍需加强

这是答辩最后需要重点讲清楚的部分：本文完成了完整系统闭环，验证了多模态融合和 OpenVINO 部署的可行性，同时也明确了当前系统的主要不足和后续方向。

结论 1：系统链路完整

系统完成视频输入、预处理、三模态特征构建、模型推理、结果显示、日志记录和样本采集，具备完整应用流程。

结论 2：实时性较好

OpenVINO FP 平均推理延迟约 23.64 ms，能够支撑普通 CPU 条件下的实时识别演示。

结论 3：总体效果可用

OpenVINO clip12 验证集总体准确率为 86.26%，standing、clapping 和 sitting 等类别识别较稳定。

不足 1：步态类动作易混淆

running 与 walking 主要依赖下肢节奏和位移变化，近景画面下下肢信息不完整时仍容易混淆。

不足 2：真实样本还需扩充

不同光照、拍摄距离、入镜比例和人物差异仍需继续补充，以提升复杂场景下的泛化能力。

后续方向

继续补充真实场景数据，优化时序建模和融合策略，并扩展更多动作类别。

Evaluation

实验结果：OpenVINO FP 是当前演示版本的平衡点

从验证集准确率看，standing、sitting 和 clapping 表现稳定；从实时性看，OpenVINO 相比原始 PyTorch 推理明显降低延迟。INT8 更快，但准确率下降，因此当前答辩演示更适合使用 OpenVINO FP 版本。

Defense Q&A

答辩可能被问到的问题，可以提前准备这几句

数据是怎么来的？

围绕六类动作整理视频片段作为训练与验证基础，系统还提供样本采集模块，可通过普通摄像头录制真实场景动作视频并按类别保存，用于后续回流训练。论文中的 7702 是 OpenVINO clip12 验证集统计样本量。

为什么用多模态？

单帧 RGB 容易受光照、背景和入镜范围影响；光流能补充动作节奏和运动变化；姿态关键点能突出人体结构。三类信息融合后更适合普通摄像头近景场景。

为什么最终选 OpenVINO FP？

PyTorch 平均延迟较高，INT8 虽然最快但准确率下降明显。OpenVINO FP 在 23.64ms 平均延迟和 86.26% 准确率之间取得了更适合演示和实际运行的平衡。

为什么 running 准确率低？

近景摄像头下下肢经常不完整入镜，而 running 与 walking 的差异高度依赖下肢节奏和位移变化；样本分布有限时，两者边界会更接近，因此后续需要补充真实场景样本并优化时序建模。
